# What is this

This is the server part of the Lua Dispatcher System for MaSzyna.
It is intended to be ran by the simulator itself.

# How to run

The code shared with the client is in the `lua/core` directory, which is a git submodule
([LuaDispatcherSystem_CORE](https://github.com/MaSzyna-EU07/LuaDispatcherSystem_CORE)).
Clone this repository with `git clone --recurse-submodules`, or run `git submodule update --init` in an existing clone.
Without it the `lua/core` directory is empty and the server does not start.

Copy the `lua` directory to the main MaSzyna directory. This is temporary, as I don't really want those scripts to be there.

I'd advise to make a script which copies the directory to your root MaSzyna directory so that the running copy is separated from the git repository.

The most important principles for a scenery to work in Lua are:

- Tracks need to be isolated so that their occupance can be tracked
- There must be no other events running that would interfere with the state of switches, semaphores etc.
  - This includes automatically closing semaphores (`_s1` events assigned to tracks)!
- `config joinduplicatedevents true endconfig` must exist before calling the `lua` directive
- `lua luascript/<SCRIPT_NAME>.lua` is actually including the primer script for your scenery of choice.

The primer scripts are located in `scenery/luascript/*.lua` and look like this:

```lua
-- Zaladuj system Lua
local DS = require("lua.main")
local config = {
	scenario = "lk2dev",
	filename = "scenery/luascript/lk2dev.json"
}
DS.init(config)

-- You can put your custom code here
```

The `scenario` field is the scenery name, which will be the name the dispatcher log files will be saved so you can identify them.

The `filename` field is the path to the project file which you can export from the client (editor).
